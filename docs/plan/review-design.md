## Findings

1. **major** — Spacing subset contradicts the direction doc. **Where:** plan line 110 (K5): "the 4/8/12/16/24/32/48/64 spacing subset". **Evidence:** `design-direction-instrument.md` §Spacing: "Use `{4, 8, 12, 16, 24, 32, 48}`. 64 is omitted: if 48 is not enough the layout is wrong, not the scale." **Fix:** In plan line 110, replace `the 4/8/12/16/24/32/48/64 spacing subset` with `the 4/8/12/16/24/32/48 spacing subset`. (Per the review constraint: report only, no edit.)

2. **major** — Motion ceiling contradicts the direction doc; the property list is unpinned. **Where:** plan line 28: "Motion is at most 150 ms of CSS transition on named properties". **Evidence:** `design-direction-instrument.md` §Motion budget: "**90 ms** micro … **140 ms** standard … **200 ms** ceiling (height/opacity on `<details>` indicators). Only named properties ever transition: `background-color`, `color`, `box-shadow`, `opacity`, `outline-color`, `transform`"; easing `cubic-bezier(0.22, 1, 0.36, 1)`. `autoplan-design.md` DES-09 adds: transitions ≤150 ms ease-out, no keyframes on first paint, one CSS-only CI spinner. **Fix:** In plan line 28, replace the sentence with: "Motion is transitions on `background-color`, `color`, `box-shadow`, `opacity`, `outline-color`, and `transform` only, at most 150 ms, easing `cubic-bezier(0.22,1,0.36,1)`, all gated by `prefers-reduced-motion: no-preference`. No keyframe animation on first paint. One CSS-only CI spinner is permitted." Then note that `design-direction-instrument.md`'s 200 ms `<details>` tier must be lowered to 150 ms when the corpus lands (a corpus edit, flagged for the implementer).

3. **major** — Render budgets are contradictory and unmeasurable as written. **Where:** plan line 194: "page render p95 at most 50 ms warm and 150 ms cold." **Evidence:** `rendering-design.md` §12.1: all budgets are cold, per-route, 3 ms (tree) to 260 ms (F8 split diff); §12.3 "No cache in v1" makes "warm" undefined. `verification-strategy.md` §7 states a third set: HTML ≤200 ms, JSON ≤100 ms, `info/refs` ≤150 ms, search ≤500 ms, measured with `RUK_BIN=ruk/target/release/ruk` over ≥1000 samples after 100 warmups. Three different tables, one undefined term, no fixture or runner named in the plan. **Fix:** Replace the sentence with: "Page render budgets are the per-route cold budgets in `rendering-design.md` §12.1, measured per §12.2: replayed Ruk fixtures, nearest-rank p95, recorded reference runner. The end-to-end budgets in `verification-strategy.md` §7 apply on the release binary with `RUK_BIN=ruk/target/release/ruk`. Reconcile the §7 numbers with §12.1 when the corpus lands."

4. **major** — Font decision conflicts with the CSP. **Where:** plan line 110 CSP `default-src 'none'` (no `font-src`) and the K5 verbatim token list, which omits typography. **Evidence:** `design-direction-instrument.md` §Typography: Space Grotesk, Source Sans 3, IBM Plex Mono, "self-hosted in production". `rendering-design.md` §4: "No web fonts. `default-src 'none'` blocks them. Typography uses system stacks." `autoplan-design.md` DES-08: "system UI + system monospace stacks only (no webfonts)". `default-src 'none'` blocks even same-origin fonts, so self-hosting cannot work under the stated CSP. **Fix:** Add to K5: "Ship no font files. The Instrument stacks resolve to their system fallbacks, per `rendering-design.md` §4 and DES-08." (Adding `font-src 'self'` plus font files is the alternative; it widens the deployed CSP and needs a user yes.)

5. **major** — UI surfaces are not assigned to steps; the console has no route. **Where:** plan line 213: "The supervision surfaces (gap work-list, branch view, batch forms) ship with F3" vs plan lines 122–131 (F3–F6). **Evidence:** F3 (line 122) names the gap work-list and branch view but no batch form. No step names the DES-17 ops console. `url-information-architecture.md` §4.1 has no `/ops` page; its `site.home` dashboard lists inbox count, review queue, tasks, CI failures — not the supersede radar, cross-repo claims, mirror backlog, ambiguous queue, or batch parade DES-17 requires. F4 (line 124) names no page; F6 (line 128) names none; F8 names none. F1 names org/team settings but no auth pages. **Fix:** Append to F1: "Ship the login, TOTP enrollment, token, and session pages." Append to F3: "Ship the ops console page at the route `url-information-architecture.md` assigns, and the batch landing parade form. One submission runs N serial land plans; it never runs one batch plan." Append to F4: "Ship the run list, the job page with step table, the log page, and the repo CI tab." Append to F6: "Ship mirror settings and status under repo settings." Append to F8: "Ship the stars, watches, forks, and releases pages." Add a route for the console to `url-information-architecture.md` or declare `site.home` the console and extend its documented columns.

6. **major** — `autoplan-design.md` rows are stale against the chosen direction and the route-map owner, with no precedence rule. **Where:** plan "Critical files" precedence covers only `ruk-changeset.md` vs named artifacts. **Evidence:** `autoplan-design.md` DES-01 picks "operations ledger" (the settled direction is Instrument). DES-02 taxonomy uses `/ops`, `/review`, `/-/admin`, and repo tabs `code|changes|branches|tasks|ci|releases|mirrors|settings`; `url-information-architecture.md` uses `/changes` (no `/review`), flat `/admin`, mirrors under settings, branches on the secondary row. DES-06 names tokens `--fg`, `--surface-1..3`, `--status-*` with a per-user `data-scheme` override; instrument tokens are `--ink`, `--s1..s3`, `--ok` with `prefers-color-scheme` only. DES-08 mandates system stacks (see finding 4). **Fix:** Add to K5: "Where `autoplan-design.md` disagrees with `design-direction-instrument.md` or `url-information-architecture.md`, the latter two govern. DES-09 and DES-11 through DES-21 still apply."

7. **minor** — The instrument specimen violates the CSP and the zero-JS gate it is meant to baseline. **Where:** `design-direction-instrument.md` footer calls `design-direction-instrument.html` "the visual-diff baseline". **Evidence:** the specimen embeds a `<style>` element and uses inline `style=` throughout: `<span style="flex:1">`, `<div class="flash" style="background:var(--info-tint)">`, `style="font-size:20px"`, `style="text-align:right"`. `rendering-design.md` §5: "`style-src 'self'` … the browser also refuses `<style>` elements and `style=` attributes"; `htmlcheck` rejects attribute `style` (§11). The specimen also shows pre-rename text `ruk forgejo serve` (plan R2 deletes that spelling). **Fix:** Add to K5: "`design-direction-instrument.html` is illustrative markup, not a render baseline. Lift its inline styles to classes (for example `flash-info`) before any use; its embedded `<style>` block and `ruk forgejo` strings are pre-decision."

8. **minor** — `zerojs.Assert` is under-specified and mischaracterized. **Where:** plan line 110: "`internal/web/zerojs.Assert` fails a test when a rendered page contains `<script`, an `on*=` attribute, a `javascript:` URL, or a `style=` attribute." **Evidence:** `rendering-design.md` §11: `htmlcheck.Check` tokenizes tag names and attribute keys only (byte-substring matching removed); rejects tag `script`, attribute keys `on[a-z]+`, `style`, URL attributes (`href, src, action, formaction, poster, data, srcset, xlink:href`) whose normalized value starts `javascript:` or `vbscript:`, and `data:` URLs except `img` `data:image/{png,gif,jpeg,webp,svg+xml}`; `zerojs.Assert` wraps `Check`; `trusted.Markdown` runs it at runtime fail-closed; `TestAllHTMLRoutesZeroJS` covers every HTML route plus the CSP header check. **Fix:** Replace the sentence with: "`htmlcheck.Check` tokenizes tag names and attribute keys. It rejects `script` tags, `on*` attribute keys, `style` attributes, `javascript:`/`vbscript:` URL attributes, and `data:` URLs outside the `img` allowlist. `zerojs.Assert` wraps it; `TestAllHTMLRoutesZeroJS` covers every route and the CSP header. `trusted.Markdown` runs it fail-closed at runtime."

9. **minor** — The WCAG sentence is incoherent. **Where:** plan line 213: "WCAG 2.2 AA applies, with 2.4.7 and 1.4.11 substituted where the target is AAA-only." 2.4.7 and 1.4.11 are AA criteria; they cannot substitute for an AAA criterion, and "the target" is undefined. **Evidence:** `autoplan-design.md` preamble: "WCAG 2.4.13 is AAA not AA (substitute 2.4.7 + 1.4.11)"; §4 and DES-21 give the concrete pass set (1.4.3 ≥4.5:1, 1.4.11 ≥3:1 non-text, 2.4.7 focus-visible, 2.5.8 ≥24 px targets, reflow, reduced-motion, forced-colors). **Intended rule:** where a stated requirement is AAA-only (2.4.13 Focus Appearance), verify the AA criteria 2.4.7 Focus Visible and 1.4.11 Non-text Contrast instead. **Fix:** Replace the clause with: "WCAG 2.2 AA applies. Where a design requirement is AAA-only (2.4.13), verify 2.4.7 and 1.4.11 instead. DES-21 is the pass set."

10. **minor** — The meta-refresh open question is never ratified, but F4 needs it. **Where:** plan lines 124 (F4) and 28 (zero-JS decision); no meta-refresh rule anywhere in the plan. **Evidence:** `autoplan-design.md` open question: "`<meta refresh>` legality inside 'zero-JS' … Ratify." DES-16 specifies the CI log page as "plain-text … opt-in meta-refresh (≥15 s) while running + terminal state on finish (no streaming — rejected)". `rendering-design.md` §5: "`<meta http-equiv=\"refresh\">` is not governed by CSP and remains allowed". **Fix:** Add to K5: "Meta refresh is allowed: only on declared live surfaces, clamped to at least 15 s, user-toggleable, and suppressed on pages with an editable form, per DES-03 and DES-16."
