## Findings

1. severity: blocker. where: "run `rukie bootstrap`, `rukie auth.login`, and `repo.create` through the CLI" (check 7). evidence: op-table-design.md §13.1 splits names on dots, so `issue.create` becomes `rukie issue create`. `repo.create` also lacks the `rukie` prefix. fix: Replace the step with three exact commands. Keep `rukie bootstrap --config <file> --username <name>` unchanged. Bootstrap is a local setup command, not an op-derived command. Change `rukie auth.login` to `rukie auth login --username ada`. Change `repo.create` to `rukie repo create --owner ada --name hello --json`. Use space-separated words for every op-derived command.
2. severity: major. where: "Serve `/-/mcp` as stateless Streamable HTTP" (F9). evidence: op-table-design.md §12.5 serves `/mcp`. usage-surface-draft.md §1.2 serves `/api/mcp`. url-information-architecture.md §3 reserves `/-/mcp` as plumbing. fix: Keep `/-/mcp` as the single path. Update op-table-design.md §12.5 to register `/-/mcp`. Update usage-surface-draft.md §1.2 to name `/-/mcp`. Add a startup check that rejects the other two paths.
3. severity: major. where: "MCP serves at most 36 tools in toolsets" (DX register) plus "Filter toolsets by scope" (F9). evidence: usage-surface-draft.md counts 131 settled plus 15 provisional operations. op-table-design.md §12.6 defaults to every domain with at least one permitted tool. Scope filtering never caps the total. fix: Add a budget rule to F9. Name the default toolsets that fit 36 tools. Require an explicit `--toolsets` flag for the rest. Add a gate test that counts default tools and fails above 36.
4. severity: major. where: "`org.member.add`, `org.member.remove`, `team.create`, `team.grant`, and `team.revoke`" (F1). evidence: usage-surface-draft.md §3.3 defines `team.repo.add`, `team.repo.remove`, `team.member.add`, and `org.member.remove`. It defines no `org.member.add`, `team.grant`, or `team.revoke`. `team.member.add` requires an explicit team, so it is not a direct rename of an org-level add. fix: Replace `team.grant` with `team.repo.add`. Replace `team.revoke` with `team.repo.remove`. Report org-level membership grant as a missing operation. Define before F1 whether a direct org add exists or every add goes through an explicit team. Name the scope, idempotency, and inbox effects of the chosen semantics.
5. severity: major. where: "`repo.fork`" (F2) and the `intent.*`, `change.show`, `change.diff`, `change.blame`, `land.admin_execute`, `ask.*`, `view.*` names (F3). evidence: usage-surface-draft.md §3.4 defines `repo.fork.create`, not `repo.fork`. usage-surface-draft.md §6 defines provisional `change.list`, `change.get`, `change.diff.get`, `change.review.submit`, `change.land`, and `task.*`. It defines no `intent.*`, `ask.*`, `view.*`, `land.*`, `change.show`, `change.diff`, or `change.blame` operations. fix: Rename `repo.fork` to `repo.fork.create`. Rename the change reads to the §6 provisional names. Add one step before F3 that promotes the Intent, Ask, View, and Land op rows from provisional to settled with exact names. Check 7 cannot name its MCP tool call until that step lands.
6. severity: major. where: "RFC 9457 errors apply everywhere" (DX register) and "exit codes from error classes" (K4). evidence: op-table-design.md §4.2 plus §4.3 is the exact catalogue with HTTP status, exit code, retryability, and Ruk code mapping. usage-surface-draft.md §1.9 uses different slugs and statuses, such as `invalid-input` 422, `malformed-request` 400, and `E_LIMIT` to `overloaded` 503. url-information-architecture.md maps `E_STALE` to 409 and `E_LIMIT` to 413 or 429. op-table-design.md maps them to `stale` 412 and `limit-exceeded` 422. fix: Declare op-table-design.md §4 the canonical catalogue. Update usage-surface-draft.md §1.9 to use its slugs and statuses. Update the url-information-architecture read-write section to use its statuses.
7. severity: major. where: "`Idempotency-Key` is store backed for 24 h" (K4) and "Idempotency-Key holds 24 h" (DX register). evidence: op-table-design.md §7 sets `IdempotencyTTL` to 24 hours. usage-surface-draft.md §1.8 retains keys for 7 days to match Ruk receipts. fix: Keep 24 hours. Update usage-surface-draft.md §1.8 to 24 hours. Keep the note that HTML `_idem` forwards as the Ruk `request_id`.
8. severity: major. where: "Weak ETags and `If-Match` guard edits" (K4). evidence: op-table-design.md §8 sets the validator quoted and strong. usage-surface-draft.md §1.7 formats ETags as `"<kind>-<id>-v<version>"`, which is strong. fix: Change the K4 line to strong ETags. Keep `If-Match` compare-and-swap inside the store transaction.
9. severity: major. where: quickstart chain "bootstrap, login, create repo, stock git push" (D1) executed through the CLI. evidence: usage-surface-draft.md §3.4 makes `repo.create` a session op. `auth.token.create`, org, team, and inbox ops are session ops too. op-table-design.md §§13.3 to 13.4 and §12.5 define only bearer credentials through `--token-file` and `RemoteInvoker`. No section defines CLI session cookie storage. fix: Add a CLI session rule to K4 and F10. Name a session file flag. Make `auth login` write the cookie jar to it. Make every later command send it.
10. severity: major. where: "Fill every number from a measurement" (D1) with a "quickstart under 5 minutes". evidence: docs-readme-draft.md states the `rukie-doccheck` harness and its scenario files are proposed tooling and do not exist. No PLAN step builds them. fix: Add a D1 step that builds the measurement harness before any number ships. Block README publication on the harness gates. Keep placeholders unresolved until then.
11. severity: major. where: "The same URL returns HTML for a browser Accept header" (check 3). evidence: url-information-architecture.md §1 rule 1 declares `text/html` the default. op-table-design.md §9.1 counts an absent header as `*/*` and orders JSON before Markdown before HTML when the header gives no order. autoplan-dx.md §2.5 declares JSON the default with HTML human-only in browsers. A curl default of `Accept: */*` therefore has two declared defaults. fix: State one precedence rule in K4. Give `*/*` and absent-header requests one deterministic media. Name one exact browser Accept value in check 3. Add `*/*` and empty-header cases to the negotiation matrix test.
12. severity: minor. where: "a quickstart under 5 minutes (bootstrap, login, create repo, stock git push)" (D1). evidence: K6 Smart HTTP Basic auth uses the username plus the full `rk_` token as password. Token minting needs `auth.token.create`. D1 omits that step. fix: Insert token creation between repository creation and the push. Name the `repo:write` scope in the step.
13. severity: minor. where: "Every step runs through the one operation table" (check 7). evidence: usage-surface-draft.md §5 places the Smart HTTP and SSH git wire outside the operation table. `bootstrap`, `runner`, `job-exec`, `backup`, and `restore` are hand-written local commands with no op rows. fix: Qualify the sentence. State that git push travels the git wire with token scopes. List the hand-written commands as explicit exceptions. Reserve their names against the derived command tree.
14. severity: major. where: token scope vocabulary across PLAN, F9, and the agent-token flow. evidence: usage-surface-draft.md §2 lists 14 colon scopes as the authoritative auth-design §8.2 list. autoplan-dx.md §2.4 uses a different colon set with different verbs, including `change:read|write|land`, `task:read|claim`, `ci:admin`, `mirror:run`, and `org:read|admin`. op-table-design.md §3.5 defines 27 `Scope` vars with names neither list uses, including `issue:*`, `session:*`, `account:create`, `public:read`, `site:admin`, `token:admin`, and `task:claim`, plus `PrincipalAgent` with `OnBehalf`. The settled rule keeps agents on human tokens with no agent principals. fix: Declare auth-design §8.2 the sole vocabulary. Replace the §2.4 and §3.5 scope lists with it. Remove `PrincipalAgent` or gate it behind an explicit user decision. Align MCP filtering and the 401 and 403 messages to the surviving names.
15. severity: major. where: "rootless podman only (exit 78 with a named error when missing)" (F4) and the runner contingency repeating exit 78. evidence: op-table-design.md §4.4 lists exits 0 to 5, 64, and 65 only. It defines no 78, 66, or 77. autoplan-dx.md §2.3 proposes 64, 66, and 77 instead. fix: Add exit 78 with its meaning to the §4.4 table. Add 66 and 77 as well if the CLI keeps them. Remove 78 from PLAN if the runner uses another code. Assert the full set with one exit-code test.
16. severity: major. where: "Add the `search.code` op and page" with "a single-repo query passes the Ruk cursor verbatim" (F7). evidence: usage-surface-draft.md §1.6 and §3.7 pass the Ruk `PageCursor` through with a 30-second lease and restart from the first page on expiry. op-table-design.md §8 requires HMAC keyset cursors that stay replayable with `Link: rel="next"`. A `Link` follower after lease expiry receives `E_LEASE_LOST`. fix: Carve an explicit search exception in op-table §8. Emit no `Link` header for Ruk-cursor pages, or wrap the Ruk cursor in the HMAC envelope. Align the limit defaults across the op rows. Cover expired-lease Link replay in the pagination tests.
17. severity: major. where: toolset domain filtering (F9, op-table §12.6) and the README agent example. evidence: op-table-design.md §12.6 filters by 16 first-segment domains that omit `auth`, `code`, `branch`, `tag`, `search`, `star`, `explore`, `team`, `admin`, and `change`. usage-surface-draft.md §1.1 lexicon uses a different domain set. docs-readme-draft.md shows dotted `rukie task.list`, `rukie task.claim`, and `rukie change.list`, while `change` rows stay provisional. fix: Unify one domain vocabulary across both files. Correct the README examples to space-separated commands. Exclude provisional tools from default MCP, CLI docs, and `llms.txt` until their names settle.
